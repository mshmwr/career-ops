將 KYC 驗證轉換率從 12% 提升至 20%

Binance ・ KYC Team ・ 2022–present
12% → 20% 7-day KYC 轉換率
12.19% → 20.03%
~50% Schema config 開發
時間縮短（AI 工作流）
背景 / 問題

原本的 KYC 驗證流程把邏輯寫在 component 和 hook 裡，每新增一個國家或驗證情境就要修改多處程式碼，上線週期長、容易出錯。

我做了什麼
  • 將整個驗證流程遷移至新專案，以前端維護的 config 檔動態渲染各種驗證情境 UI，移除散落各處的 hard code 邏輯
  • 把散落在各國的 component 和 hook 邏輯集中管理，讓新市場接入從「多處同時修改」變成「在一個位置進行更新」
  • 導入 AI 輔助工作流（Cursor + Claude Code），以現有 config + Figma 截圖為 context，自動生成新 config 草稿，約縮短 50% 開發時間
  • 透過 A/B 實驗設計與數據驗證驅動 UX 決策，確認上線後轉換率確實提升再全量推送

成果 3 — 前端效能優化

設計 Webview Pool，讓桌機應用載入速度提升 30%

Binance ・ Electron Team ・ 2021–2022
+30% Webview 載入速度提升
（預載 + 快取複用）
Pool 設計模式
預建實例 → 切換直接複用
Memory single/multi-process
依裝置效能彈性切換
背景 / 問題

Binance 桌機交易平台整合多個 micro-app，用戶每次切換功能都需從頭初始化一個新的 Webview，造成明顯延遲。流量愈高、切換愈頻繁，體驗就愈差。

我做了什麼
  • 設計並實作 Webview Pool：應用啟動時預先建立 Webview Pool，切換時直接取用已備好的 Webview，省去每次初始化的成本
  • 加入快取策略，讓常用的 micro-app 保持預載狀態，進一步縮短冷啟動時間
  • 開發 single/multi-process 切換功能，讓使用者依裝置記憶體選擇「效能優先」或「資源節省」模式，解決高規與低規裝置的不同需求
